# Python Security Lab

Учебное локальное Flask-приложение с двумя намеренно реализованными уязвимостями и исправленными вариантами.

## Что демонстрируется

- **OWASP A03:2021 — Injection (SQL Injection):** уязвимый маршрут строит SQL через конкатенацию строк; исправленный использует placeholders `?`.
- **OWASP A01:2021 — Broken Access Control (IDOR):** уязвимый маршрут позволяет запрашивать профиль по ID без проверки владельца; исправленный требует сессию и сверяет ID.

## Требования

- Python 3.10+
- Windows PowerShell или другой терминал

## Установка на Windows

Открой PowerShell в папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Если PowerShell запрещает активацию окружения, можно не активировать его, а вызвать Python напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

## Запуск

```powershell
python app.py
```

Открой в браузере: http://127.0.0.1:5000

Сервер привязан только к `127.0.0.1` и не должен быть выставлен в интернет или локальную сеть.

## Тестовые аккаунты

| Пользователь | Пароль | ID |
|---|---|---:|
| alice | alice123 | 1 |
| bob | bob123 | 2 |

Это исключительно демонстрационные данные. Не используй реальные пароли.

## Демонстрация SQL Injection

При работающем сервере, в другом терминале:

```powershell
python exploits/sql_injection.py
```

Скрипт сравнит уязвимый и исправленный маршруты. Ожидается, что уязвимая версия примет специально сформированное значение, а исправленная вернёт отказ в авторизации.

## Демонстрация IDOR

```powershell
python exploits/idor.py
```

Скрипт входит как Alice и пытается получить профиль Bob (ID 2). Уязвимая версия отдаёт демонстрационный профиль, исправленная отвечает HTTP 403.

## Где находятся исправления

- `app.py`, функция `login`: параметризованный SQL-запрос в ветке `patched`.
- `app.py`, функция `profile`: проверка сессии и соответствия ID пользователя в ветке `patched`.

## Сброс базы

Останови сервер, удали `lab.db`, затем снова запусти `python app.py`. База будет создана заново.

## Ограничения и безопасность

Это намеренно уязвимая учебная лаборатория, а не production-приложение. Пароли хранятся открытым текстом для наглядности, CSRF-защита и полноценная система управления пользователями не реализованы. Не подключай приложение к внешнему интерфейсу, не публикуй его и не используй реальные данные.
